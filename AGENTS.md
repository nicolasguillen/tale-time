# Tale Time

A picture-book choose-your-own-adventure app for kids (Android + iOS, Kotlin/Compose Multiplatform like Nim), plus the content pipeline that makes its stories. The pipeline is the real product. [plan.md](plan.md) is the living plan; [docs/story-format.md](docs/story-format.md) is the story and catalog format.

## Hard rule: never generate images or audio if the user did not agree with to do so

- **Don't generate, render or synthesize any image**: no image-model or diffusion API calls, no AI image tools, and no procedurally drawn illustrations, character art, covers or cards (Pillow, ImageMagick, canvas, SVG art). This covers story images, reference sheets, app icons, store art and screenshots made to look like content. Plain UI chrome in the app (icons, buttons) is fine.
- **Don't generate any audio either**: no text-to-speech, voice models, voice cloning or synthesized narration, in the repo, the pipeline or the app.
- **Use the static placeholders** in `content/placeholders/` (`page.svg`, `card.svg`, `cover.svg`, `sheet.svg`) wherever an image is missing. Don't add new placeholder art. A new kind of image gets one plain placeholder in the same style only if the user agrees. A story without narration simply shows its text.
- **The user generates the images with AI, outside the repo**, by pasting the prompts in the story's `REQUESTED_ASSETS.md` into an AI image tool (ChatGPT or the GPT Image API). Your job is to write the requests, never to run them.
- **Request every image in a `REQUESTED_ASSETS.md`** and **every narration clip in a `REQUESTED_AUDIO.md`**, with their specs, descriptions and ready-to-paste prompts. **Each story's images are requested in its folder** (`content/stories/<id>/REQUESTED_ASSETS.md`, next to `images/`; the pictures are the same in every language). **Its narration is requested once per language, inside the folder those clips go into** (`content/stories/<id>/audio/<lang>/REQUESTED_AUDIO.md`), written in that language for that language's narrator: `audio/en/` in English, `audio/es/` in Latin American Spanish. The files at the root are only indexes: the status of each story (and language) with a link to its files, how to make and deliver, the narrators, and the app icon. All of them are generated by `cd tools && uv run story assets`: change the sources instead (a shot in the story's `shots.json`, a cast member, prop or `pronounce` hint in `bible.json`, the words in `story/<lang>.json`, names, refrains and moods in another language in `translations/<lang>.json`, the story's art style in its `style/style.json`, the narrator of each language in `content/style/voice.json`, the app icon in `content/app/assets.json` and `content/app/style.json`).
- **Every story has its own art style and its own characters.** Its style (`style/style.json`, with its style anchor) and its reference sheets (`characters/`) live in its folder. Two stories share a style or a character **only when the user asks for it**, declared in the bible: `styleFrom: "<story-id>"` reuses that story's style and anchor, and `from: "<story-id>"` on a cast member or prop reuses that story's character, with the same look word for word and its sheet. Never share by default, and never reuse another story's style or cast because it's convenient.
- The user delivers images and audio into the folders named there. Treat delivered files as read-only. Packaging may resize and convert images to WebP, and convert audio to AAC and even out its loudness, nothing else.
- **Delivered files aren't in git** (see "Git"). After every delivery run `cd tools && uv run story originals push`: until then the file exists only on this computer. It's a private backup, not publishing, so it needs no extra ask.

## No API keys

- The writing steps (seeds, bible, outline, text, editor pass, shots) are done **by Claude in Claude Code**, through the `/new-story` skill (`.claude/skills/new-story/`), following `tools/prompts/<step>.md`. Don't add code that calls a model API, and don't ask for `ANTHROPIC_API_KEY`.
- The `story` CLI is deterministic: checks, status, paths, asset and audio requests. No network.

## Other rules

- **No runtime AI in the app.** Every story is made ahead of time and reviewed by a person.
- **Collect nothing.** No accounts, ads, analytics or crash SDKs, no Firebase SDK. The only permission is INTERNET, to download the catalog and the stories; nothing is sent.
- **Free and paid stories.** `content/catalog.json` is the shelf: each story is `free` or `paid` (a one-time purchase with a `product` id, the same on both stores). The first story, *The Fox and the Lantern*, is free. No story ships inside the app: each one is downloaded (below). Anything that buys, restores or leaves the app goes behind the **parental gate**.
- **No text inside images.** The app draws all titles and labels.
- **Node ids never change** once a story version is published.
- Publishing content (`story publish`, draft or production), deploying Firebase changes and store uploads happen only when the user asks.

## Pipeline commands (from `tools/`)

```
uv run story check [<id>…] [--strict] [-v]   validate the catalog, the app images and every stage of the stories (--strict = publishing)
uv run story status [<id>…]                  which steps are done, what's next, images and narration delivered
uv run story paths <id> [--all] [--lang es]  print play-throughs as Markdown (from the outline until story/ exists)
uv run story assets [--check]                regenerate every REQUESTED_ASSETS.md and REQUESTED_AUDIO.md (root, per story, per language)
uv run story icons [--check]                 put the delivered app icon into both apps (Android launcher layers as WebP per density, iOS AppIcon)
uv run story package [draft] [production]    build what the app downloads into content/.build/stories/<channel>/ (WebP, AAC, word timings, manifests, catalog)
uv run story publish <draft|production> [--dry-run]  upload a channel to Firebase Storage (stories/<channel>/), only when the user asks
uv run story originals [push|pull] [--dry-run]  the delivered pictures and clips (not in git): status, upload new ones to Firebase
                                             Storage (originals/) after a delivery, download missing ones after a clone
                                             (package and publish pull what's missing first; publish also pushes)
uv run pytest -q                             tests (they also fail if either requests file or the apps' icons are stale, or an original isn't here)
```

## Writing stories

- Use `/new-story` and its prompts in `tools/prompts/`. They hold the craft and safety rules; what follows is the short version.
- The craft guides in `tools/prompts/craft/` hold the storytelling knowledge: **values** (one per story, shown and never told), **structures** (the shape, the hero's arc, and how each shape branches) and **ages** (what each band can follow and feel). Every bible names its value, shape and arc in `craft`. No rhyming books.
- Follow the bible: the cast's looks, the world rules and the **"never" list**. Invented names get a `pronounce` hint for the narrator.
- Budgets per age band are in `tools/storytool/budgets.py` and docs/story-format.md.
- Merge pages must make sense from every path into them, in the text and in the picture. Side characters met on a branch leave before the merge.
- Choices are about character, not luck. Both options sound fun, and consequences show up within a page or two.
- Every story gets a `review.md`. The user reads every path before anything is published.
- **Languages.** Stories are written in English first, then translated (step 6, `tools/prompts/translate.md`). **Spanish (`es`) means Latin American Spanish:** tú, never vos or vosotros, and words that read the same from Mexico to Argentina. A translation is a retelling, inside the same word budgets, with its names, refrains and moods in `translations/<lang>.json`. It stays `"status": "draft"` until a native speaker reads every path (`uv run story paths <id> --lang es`); record its narration only once it's `approved`. **One file per language:** `story/en.json` is the whole story in English, `story/es.json` the whole story in Spanish (with `"translatedFrom": "en"`), with the same nodes, ids, links and images; only the words differ, and `story check` holds every translation to the first language's structure. A change to the English text changes every translation of that page too.
- A new story goes on the shelf by adding it to `content/catalog.json` (free or paid). It reaches debug builds through `story publish draft` and release builds through `story publish production` (see "Distribution").

## App

Same stack and conventions as Nim: Kotlin 2.4, Compose Multiplatform, AGP 9, Gradle 9 (version catalog in `gradle/libs.versions.toml`), Koin, Navigation Compose with `@Serializable` routes, Room 3 (KSP), DataStore, Coil 3 (with SVG for the placeholders), ktlint. Package root `com.nicolasguillen.taletime`; app id / bundle id `com.nicolasguillen.taletime`; display name **Tale Time**; product name `TaleTime`.

Packages in `shared/src/commonMain/kotlin/com/nicolasguillen/taletime/`:

```
story/         pure Kotlin (stdlib + serialization): Story model, StoryParser, StoryGraph checks, Reading (start, next, choose, back, resume), Pacing (when each word appears)
domain/        CatalogEntry (free/paid), StoryLibrary, ProgressRepository, SettingsRepository (text size, Language), Purchases, Book + shelf()
data/          HostedStoryLibrary (catalog, downloads per language, updates, on-device files), ContentSource, local/ Room + DataStore
platform/      platformModule (expect/actual): file locations, BuildInfo, NarrationPlayer (MediaPlayer / AVAudioPlayer)
designsystem/  TaleColors, Andika typography, TaleIcons, StoryImage (placeholder fallback), buttons, EndingBadge
i18n/          Strings: every word the app itself shows, one complete Strings per language; LocalStrings, LocalLanguage
feature/       shelf/, cover/ (Read/Continue, endings, unlock), reader/ (pages, forks, endings, back), parents/ (gate + parents area)
navigation/    Routes + TaleNavHost        di/  Koin modules
```

- **Stories are downloaded, never bundled** (see "Distribution" below). The `bundleContent` Gradle task (`shared/build.gradle.kts`) only writes `files/shelf.json` (the shelf's titles, shown until the first launch online) and copies `content/placeholders/*.svg` into the app's resources, next to the fonts in `shared/src/commonMain/appResources/`. Don't put resources in a `composeResources` folder: that custom directory replaces it.
- **Tests read the pipeline's own files.** The `generateFixtures` task turns `schema/fixtures/<name>/story/<lang>.json`, every `content/stories/*/story/<lang>.json` and the catalog into `fixtures/Fixtures.kt` for `commonTest`, so the app checks every real story (parses, graph rules, every path ends).
- **Languages:** the app speaks English and Latin American Spanish (`domain/Language`). A grown-up picks one in the parents area; until then it's the device's language (`platform/deviceLanguage()`), else English. **No user-facing text in a screen:** every word the app shows or reads to a screen reader goes in `i18n/Strings.kt`, in every language. `StoryParser` reads the language files on the device into one `Story` (a translation can be there without the language it came from). A story is read in the language picked on its cover when it was downloaded (`Installed.reading`); the app's language is only the one offered first. Picking another keeps the reader's place, because progress is kept by node id. A new language needs a `Language` entry, a `Strings`, `CFBundleLocalizations` in `iosApp/project.yml`, a narrator in `voice.json` and its wording in `tools/storytool/audio_text.py`.
- **Narration:** every text with a delivered clip is read aloud (`feature/reader/ReaderViewModel`, the cover's title in `CoverViewModel`): a page's words appear as the narrator says them (the reading clock follows the player's position, through the timings `story package` measures), a fork reads its question then each label, an ending its title. A text without its clip reads at the narrator's pace (`story/Pacing`). Each screen that reads aloud gets its own `NarrationPlayer` and releases it; narration pauses while the app is in the background. Nothing is synthesized: no clip, no voice.
- **Paid stories:** `domain/Purchases` is bound to `UnavailablePurchases` until StoreKit and Google Play Billing are wired in, so paid stories show a lock and the unlock sheet says the store isn't connected.
- **New screen:** `feature/<name>/` with `<Name>Screen.kt` (stateless `<Name>Screen(state, onEvent, …)` plus a `<Name>Route` that gets the ViewModel with `koinViewModel()`) and `<Name>ViewModel.kt` extending `feature/StateViewModel`. Register it in `di/AppModule.kt` and `navigation/`.
- **Database change:** edit `data/local/TaleTimeDatabase.kt` and bump `version`. Room exports the schema to `shared/schemas/` (commit it) and needs a migration for existing installs.
- Visual tokens live only in `designsystem`. Keep the native hosts thin.

### Build, run, verify (from the repo root)

```
./gradlew ktlintCheck                                  # lint (ktlintFormat fixes most)
./gradlew :shared:testAndroidHostTest                  # shared tests on the JVM (fast)
./gradlew :shared:allTests                             # JVM + iOS simulator
./gradlew :androidApp:assembleDebug                    # Android APK
./gradlew :androidApp:installDebug && adb shell am start -n com.nicolasguillen.taletime/.MainActivity
./gradlew :shared:linkDebugFrameworkIosSimulatorArm64  # iOS side compiles
cd iosApp && xcodegen generate                         # after editing project.yml; never hand-edit project.pbxproj
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath iosApp/build/DerivedData build -quiet
# → iosApp/build/DerivedData/Build/Products/Debug-iphonesimulator/TaleTime.app
```

- Prerequisites: JDK 21, the Android SDK in `local.properties` (`sdk.dir=…`, gitignored), Xcode with a simulator runtime, `brew install xcodegen`.
- For visual changes, run the app on a phone **and** a tablet (both orientations on the tablet) and look at screenshots. Emulators: `emulator -list-avds` (e.g. `Pixel_9_API_36_A16`, `Tablet_10_inch`). Save screenshots in a scratch folder, never in the repo.
- The user's physical Android phone may be plugged in. Installing the debug build is fine; ask before uninstalling or clearing data on it.

## Distribution

- **Nothing ships inside the app.** The shelf lists every story in the catalog; a story is downloaded when a reader taps it and picks a language (the app's own first): its text, its pictures and that language's narration. It stays on the device to read offline (`filesDir/library` on Android, `Application Support/library` on iOS, both left out of backups). Every time the app opens online, it fetches the catalog, and a downloaded story whose manifest changed downloads only the files it doesn't have, then switches to the new version; the old files go at the next launch.
- **The published format** (docs/story-format.md, "Published stories"; `schema/published-catalog.schema.json`, `schema/manifest.schema.json`): per channel, `stories/<channel>/catalog.json` and, per story, a manifest and files named after their contents (`<name>-<sha256 prefix>.<ext>`), so a changed file gets a new name and nothing on the host is ever overwritten.
- **Two channels, both on Firebase Storage.** `draft` (`stories/draft/`) is content/ as it is (draft translations, whatever is delivered); debug builds download it (`ContentSource.Draft`). `production` (`stories/production/`) is what release builds download (`ContentSource.Production`): only stories with every picture delivered, in their first language and approved translations, each language narrated only once all its clips are there. `story publish draft` also deletes the draft files no story uses any more; `story publish production` never deletes anything. There is no local server: the draft folder's paths are guessable and readable by anyone, which the user accepted for drafts.
- **Packaging only converts:** pictures to WebP (cover 900×1200, pages 1600×1200, cards 768×768 at most), clips to mono AAC 64 kbps at −16 LUFS. The same source always gives the same file (the AAC is rewrapped without afconvert's timestamp), so an unchanged file never downloads twice. Bump `Encoder.version` in `tools/storytool/package.py` when the conversion changes.
- **Word timings** are measured at packaging from each page's delivered clip (`tools/storytool/timings.py`: pauses in the clip matched to the text's sentence and clause breaks, words spread by syllables; ffmpeg only, no model) and shipped as `timings-<lang>.json`. Bump `VERSION` there when the measuring changes.
- **To try a story on a device:** `cd tools && uv run story publish draft` (with the user's OK), then run a debug build, on any device, anywhere. A change to the content shows up in the app only after the next `story publish draft`. The iOS UI walkthrough needs the draft channel published.

## Firebase

- Project **`tale-time-b537d`** (`.firebaserc`), Storage bucket `tale-time-b537d.firebasestorage.app` (us-east1). No apps are registered and the app uses no Firebase SDK: downloads will be plain HTTPS.
- `backend/storage.rules`: anyone can read single files under `stories/` (both channels: the catalogs, the manifests and the story files), nobody can list or write. `story publish` uploads with `gcloud` (the owner's login), files first and the catalog last. `originals/` (the delivered files, `story originals`) is private: nobody can read it through the API, only the owner's gcloud login. Deploy with `firebase deploy --only storage --project tale-time-b537d`, only when the user asks. Check the project first: the CLI's default has pointed at other projects.

## Git

- **Delivered pictures and narration aren't in git.** `.gitignore` leaves out every image and audio file under `content/` (one line per extension in `IMAGE_EXTENSIONS` and `AUDIO_EXTENSIONS`; a test keeps them in step). They're kept in the bucket under `originals/`, private, named after their contents (`<path under content/>` with `-<hash>` before the extension), so a redelivered file never replaces the old original. `content/originals.json` is committed: it lists each original with its hash, so every commit says which originals it used. `story originals push` uploads (never overwrites or deletes in the bucket) and rewrites the list; `story originals pull` downloads what's missing, after a clone or a checkout, and never overwrites a file that's different here. `story package` and `story publish` pull what's missing before they build (and stop if they can't, so a story never ships without its pictures), and `story publish` pushes what isn't kept yet. `story check` warns when an original isn't pushed or isn't here.
- The app's own icon files that `story icons` writes (`androidApp/…/mipmap-*/`, iosApp's AppIcon set) stay in git: the apps build from them.
- Commit only when the user asks.
